# 轻量级外卖服务平台功能分析

## 1. 文档目的与范围

本文将课程实践手册中的阶段 1 固定需求细化为可开发、可测试的后端功能清单。手册规定 `user`、`merchant`、`restaurant`、`item`、`shopping`、`order` 六个必需业务领域；它们构成需求基线，但不限制实现时的 Spring Modulith 模块总数。本文描述目标能力，不代表当前代码已经实现；后续阶段的需求变更应追加版本和影响分析，不直接改写已验收规则。

具体 HTTP 字段见[后端 API 设计](api/backend-api-design.md)，代码边界和模块调用见[后端架构设计](architecture/backend-architecture-design.md)。

参与者分为普通用户、商家和未登录访客。普通用户只能操作本人的资料、购物车和订单；商家只能管理自己的店铺、分类和商品；公开浏览接口不要求登录。所有写操作均由后端进行身份、归属、状态和参数校验。

## 2. 用户模块（User）

| 编号 | 功能 | 关键规则与验收点 |
| --- | --- | --- |
| USER-01 | 普通用户注册 | 校验账号、密码、确认密码、昵称和联系方式；账号全局唯一；密码只保存摘要；成功后状态为 `ACTIVE`。重复账号或非法字段不产生记录。 |
| USER-02 | 用户登录 | 校验账号、密码和账号状态；成功签发访问令牌并返回非敏感身份信息；账号不存在、密码错误或 `DISABLED` 均拒绝登录。 |
| USER-03 | 查询个人资料 | 仅返回当前用户的账号、昵称、联系方式、状态和时间信息，不返回密码摘要。 |
| USER-04 | 修改个人资料 | 允许本人局部修改昵称、联系方式；不允许借此修改用户 ID、账号、角色或状态；失败时不保存部分无效数据。 |
| USER-05 | 账号有效性校验 | 向其他模块提供“用户存在且可操作”的校验能力；未认证请求返回 401，已禁用用户不能执行受保护操作。 |

## 3. 商家模块（Merchant）

本设计将商家定义为有效用户附加的经营者身份：一个用户最多创建一个商家档案，并继续使用用户模块登录。

| 编号 | 功能 | 关键规则与验收点 |
| --- | --- | --- |
| MERCHANT-01 | 注册商家 | 当前用户提交商家名称和联系方式；校验用户状态及重复注册；成功创建 `ACTIVE` 商家档案。 |
| MERCHANT-02 | 查询本人商家资料 | 返回当前用户关联的商家 ID、名称、联系方式和状态，未注册时返回 404。 |
| MERCHANT-03 | 经营权限校验 | 仅 `ACTIVE` 商家可创建或维护店铺和商品；`SUSPENDED` 商家保留历史数据但不能执行管理写操作。 |

## 4. 店铺模块（Restaurant）

内部模块名为 `restaurant`，对外 REST 资源统一使用 `shops`。

| 编号 | 功能 | 关键规则与验收点 |
| --- | --- | --- |
| SHOP-01 | 创建店铺 | 有效商家可创建店铺；名称必填，同一商家内名称唯一；初始状态为 `CLOSED`。 |
| SHOP-02 | 修改店铺资料和状态 | 店主可修改名称、简介以及 `OPEN`、`CLOSED`、`TEMPORARILY_CLOSED` 状态；状态变化不删除商品或历史订单。 |
| SHOP-03 | 浏览店铺列表 | 访客可按关键字、状态分页过滤并按白名单字段排序；无结果返回空列表。 |
| SHOP-04 | 查看店铺详情 | 返回店铺名称、简介、状态等公开信息；不存在或已逻辑删除的店铺返回 404。 |
| SHOP-05 | 店铺归属与可下单校验 | 商品管理前校验商家归属；购物车和订单操作前重新确认店铺为 `OPEN`。 |

## 5. 商品模块（Item）

内部模块名为 `item`，对外资源使用 `products` 和 `categories`。

| 编号 | 功能 | 关键规则与验收点 |
| --- | --- | --- |
| ITEM-01 | 分类新增与查询 | 商家在本人店铺创建分类；名称必填且同一店铺内唯一；公众可查询有效分类。 |
| ITEM-02 | 分类修改与逻辑删除 | 店主可修改名称和排序号；被有效商品引用的分类不得物理删除。 |
| ITEM-03 | 新增商品 | 校验店铺归属、分类归属、名称、价格和库存；价格大于 0，库存不小于 0，初始状态为 `OFF_SALE`。 |
| ITEM-04 | 修改商品 | 店主可局部修改名称、描述、分类和价格；商品改价不影响历史订单快照。 |
| ITEM-05 | 上下架与库存管理 | 店主可设置 `ON_SALE`/`OFF_SALE` 并调整库存；库存不能为负，零库存商品不可购买。 |
| ITEM-06 | 商品列表与详情 | 公众按店铺、分类和关键字分页浏览上架商品并查看价格、库存状态和详情；商家管理查询可包含下架商品。 |
| ITEM-07 | 购买快照与库存变更 | 向购物车、订单模块提供当前名称、价格、状态、库存快照；下单时原子扣减库存，取消时只恢复一次。 |

## 6. 购物车模块（Shopping）

| 编号 | 功能 | 关键规则与验收点 |
| --- | --- | --- |
| CART-01 | 加入购物车 | 登录用户添加商品和正整数数量；校验店铺营业、商品上架和库存。同一用户同一商品合并数量。 |
| CART-02 | 查询购物车 | 仅返回本人购物车，包含最新商品信息、数量、小计和失效原因；空购物车返回空列表。 |
| CART-03 | 修改数量 | 仅本人可修改；新数量必须为正且不超过库存，商品或店铺失效时明确报错。 |
| CART-04 | 删除购物车项 | 仅本人可删除；删除不改变库存和历史订单，重复删除返回 404。 |
| CART-05 | 提供结算快照 | 为订单模块返回选中购物车项；一次订单中的商品必须来自同一店铺，结算成功后仅清除已提交项。 |

## 7. 订单模块（Order）

| 编号 | 功能 | 关键规则与验收点 |
| --- | --- | --- |
| ORDER-01 | 创建订单 | 根据本人选中的购物车项创建订单；服务端重新校验用户、店铺、商品和库存并按当前价格计价，不接受客户端金额。 |
| ORDER-02 | 保证事务一致性 | 订单主表、明细快照、库存扣减和购物车清理在同一事务内完成；任一步失败全部回滚。 |
| ORDER-03 | 防止重复提交 | 同一用户使用相同幂等键重复请求时返回首次结果，不生成第二张订单；相同键不同请求返回冲突。 |
| ORDER-04 | 查询订单列表 | 用户分页查询本人订单，可按状态过滤，默认按创建时间倒序；无数据返回空列表。 |
| ORDER-05 | 查询订单详情和状态 | 仅订单所有者可查看主信息、店铺、明细快照、金额和状态；商品后续变化不影响历史展示。 |
| ORDER-06 | 取消订单 | 所有者可取消 `PENDING_PAYMENT` 订单；取消是状态迁移而非删除，并原子恢复库存；重复或非法状态取消返回 409。 |

阶段 1 不接入真实支付、退款、骑手或配送调度。订单初始状态为 `PENDING_PAYMENT`，保留 `PAID`、`PREPARING`、`DELIVERING`、`COMPLETED` 状态供后续迭代扩展。

## 8. 横向质量要求

- 所有接口使用 `/api/v1`、标准 HTTP 状态码和统一 `code`、`msg`、`data` 响应体。
- 核心接口必须先覆盖正常、异常、边界和权限测试，再实现业务代码；核心接口覆盖率 100%，关键业务方法覆盖率不低于 90%。
- 分页从 1 开始，`pageSize` 默认 10、最大 100；排序字段必须采用服务端白名单。
- 日志不得记录密码、令牌或完整联系方式；异常响应不得暴露堆栈和数据库细节。
