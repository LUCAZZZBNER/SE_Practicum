# 轻量级外卖服务平台接口设计

## 1. 通用约定

### 1.1 基本规则

- 接口前缀：`/api/v1`
- 数据格式：`application/json`
- 时间格式：ISO 8601，例如 `2026-09-06T10:30:00Z`
- 金额格式：JSON 数值，数据库保留两位小数
- 受保护接口请求头：`Authorization: Bearer <access-token>`
- 未列出的请求字段视为非法字段，返回参数错误。

接口权限使用以下标记：

- **公开**：无需登录。
- **可选身份**：无需登录即可访问；携带有效商家令牌后可使用仅限本人资源的查询选项。
- **用户**：要求 `USER` 角色。
- **商家**：要求 `MERCHANT` 角色。

### 1.2 统一返回结构

```json
{
  "code": 0,
  "msg": "操作成功",
  "data": {}
}
```

成功时 `code` 固定为 `0`。失败时 `code` 为业务错误码，`data` 通常为 `null`；字段校验失败时可返回：

```json
{
  "code": 1001,
  "msg": "请求参数不合法",
  "data": {
    "fieldErrors": {
      "account": "不能为空"
    }
  }
}
```

### 1.3 分页结构

```json
{
  "items": [],
  "page": 1,
  "pageSize": 10,
  "total": 0,
  "totalPages": 0
}
```

分页接口的 `page` 默认值为 1，`pageSize` 默认值为 10，允许范围为 1～100。默认排序字段和方向由各资源说明。

### 1.4 HTTP 状态码

| 状态码 | 含义 |
| --- | --- |
| 200 | 查询、修改、删除或业务动作成功；购物车同商品合并成功 |
| 201 | 注册、创建店铺、分类、商品、购物车条目或订单成功 |
| 400 | Body、Path、Query、Header 不合法或购物车结算条件不成立 |
| 401 | 登录凭据错误，或访问令牌缺失、无效、过期 |
| 403 | 账号不可用、角色错误或资源不属于当前主体 |
| 404 | 资源不存在，或公开访问的下架商品不可见 |
| 409 | 唯一性、状态、库存、版本或幂等冲突 |
| 500 | 未预期的服务端错误 |

## 2. 公共数据对象

### 2.1 用户与商家

`UserView` 包含 `id`、`account`、`nickname`、`phone`、`status`、`createdAt`、`updatedAt`。

`MerchantView` 包含 `id`、`account`、`name`、`phone`、`status`、`createdAt`、`updatedAt`。

登录结果包含 `accessToken`、`tokenType`、`expiresIn`、对应的 `user` 或 `merchant` 对象，以及 `roles` 字符串数组。

### 2.2 店铺、分类与商品

`ShopView` 包含 `id`、`merchantId`、`name`、`description`、`status`、`createdAt`、`updatedAt`。

`CategoryView` 包含 `id`、`shopId`、`name`、`sortOrder`、`createdAt`、`updatedAt`。

`ProductView` 包含 `id`、`shopId`、`categoryId`、`name`、`description`、`price`、`stock`、`status`、`version`、`createdAt`、`updatedAt`。

### 2.3 购物车

`CartItemView` 包含：

- `id`：购物车条目编号。
- `product`：含 `id`、`shopId`、`name`、`price`、`stock`、`status`、`version` 的商品当前信息。
- `quantity`、`subtotal`：购买数量和按当前价格计算的小计。
- `available`、`unavailableReason`：当前是否可结算及原因。
- `createdAt`、`updatedAt`：条目时间。

购物车结果包含 `items` 和按当前价格计算的 `total`。不可用原因可能为 `SHOP_NOT_OPEN`、`PRODUCT_OFF_SALE` 或 `INSUFFICIENT_STOCK`。

### 2.4 订单

`OrderSummaryView` 包含 `id`、`orderNumber`、`shopId`、`shopName`、`total`、`status`、`createdAt`。

`OrderView` 在摘要基础上增加 `userId`、`lines`、`updatedAt` 和 `cancelledAt`。每个 `line` 包含 `productId`、`productName`、`unitPrice`、`quantity`、`subtotal`。

## 3. 用户接口

| 方法与路径 | 权限 | 请求 | 成功结果 |
| --- | --- | --- | --- |
| `POST /users` | 公开 | `account`、`password`、`passwordConfirm`、`nickname` 必填，`phone` 可选且非空白 | 201，`UserView` |
| `POST /users/login` | 公开 | `account`、`password` 必填 | 200，用户登录结果 |
| `GET /users/me` | 用户 | 无 | 200，`UserView` |
| `PATCH /users/me` | 用户 | 至少提供 `nickname` 或 `phone`；昵称不能空白，电话可设为 `null` | 200，更新后的 `UserView` |

用户注册时 `password` 与 `passwordConfirm` 必须一致，账号去除首尾空白后保持唯一。登录时账号不存在和密码错误使用相同错误，避免暴露账号存在性。

## 4. 商家接口

| 方法与路径 | 权限 | 请求 | 成功结果 |
| --- | --- | --- | --- |
| `POST /merchants` | 公开 | `account`、`password`、`name`、`phone` 必填，`passwordConfirm` 可选；提供时必须一致 | 201，`MerchantView` |
| `POST /merchants/login` | 公开 | `account`、`password` 必填 | 200，商家登录结果 |
| `GET /merchants/me` | 商家 | 无 | 200，`MerchantView` |
| `PATCH /merchants/me` | 商家 | 至少提供 `name` 或 `phone`，提供值不能为 `null` 或空白 | 200，更新后的 `MerchantView` |

商家账号独立于普通用户账号；两个账号表分别保证账号唯一。

## 5. 店铺接口

| 方法与路径 | 权限 | 请求 | 成功结果 |
| --- | --- | --- | --- |
| `POST /shops` | 商家 | Body：`name` 必填，`description` 可选 | 201，`ShopView` |
| `GET /shops` | 可选身份 | Query：见下表 | 200，分页 `ShopView` |
| `GET /shops/{shopId}` | 公开 | `shopId` 为正整数 | 200，`ShopView` |
| `PATCH /shops/{shopId}` | 商家 | 至少提供 `name`、`description`、`status` 之一 | 200，更新后的 `ShopView` |

新店铺状态固定为 `CLOSED`。同一商家下店铺名称不能重复。修改接口只允许店铺所有者使用；`description` 可以显式设为 `null`，`status` 只能是 `OPEN`、`CLOSED`、`TEMPORARILY_CLOSED`。

店铺列表参数：

未使用 `mine=true` 时，列表只返回营业中的店铺；商家使用 `mine=true` 后可以查看自己名下的全部状态并按状态筛选。

| 参数 | 规则 |
| --- | --- |
| `page`、`pageSize` | 页码与页大小 |
| `keyword` | 店铺名称关键字，空白按未提供处理 |
| `status` | `OPEN`、`CLOSED` 或 `TEMPORARILY_CLOSED` |
| `mine` | 为 `true` 时仅查询当前商家店铺，必须携带商家令牌 |
| `sortBy` | `name` 或 `createdAt`，默认 `createdAt` |
| `sortOrder` | `asc` 或 `desc`，默认 `desc` |

## 6. 分类接口

| 方法与路径 | 权限 | 请求 | 成功结果 |
| --- | --- | --- | --- |
| `POST /shops/{shopId}/categories` | 商家 | Body：`name` 必填，`sortOrder` 可选且不小于 0 | 201，`CategoryView` |
| `GET /shops/{shopId}/categories` | 公开 | `shopId` 为正整数 | 200，分类数组 |
| `PATCH /categories/{categoryId}` | 商家 | 至少提供 `name`、`sortOrder` 之一 | 200，更新后的 `CategoryView` |
| `DELETE /categories/{categoryId}` | 商家 | `categoryId` 为正整数 | 200，`{ "id": ..., "deleted": true }` |

分类名称在同一店铺内唯一。列表按 `sortOrder`、`id` 升序返回。分类只能由店铺所有者维护；仍有商品引用时不能删除。

## 7. 商品接口

| 方法与路径 | 权限 | 请求 | 成功结果 |
| --- | --- | --- | --- |
| `POST /products` | 商家 | `shopId`、`categoryId`、`name`、`price`、`stock` 必填，`description` 可选 | 201，`ProductView` |
| `GET /shops/{shopId}/products` | 可选身份 | Query：见下表 | 200，分页 `ProductView` |
| `GET /products/{productId}` | 可选身份 | Query：`includeOffSale`，默认 `false` | 200，`ProductView` |
| `PATCH /products/{productId}` | 商家 | `version` 必填；可同时提供分类、名称、说明、价格、库存或状态 | 200，更新后的 `ProductView` |

商品创建规则：

- `shopId`、`categoryId` 为正整数，分类必须属于指定店铺。
- `price` 大于等于 0.01，最多两位小数；`stock` 不小于 0。
- 新商品状态为 `OFF_SALE`，初始版本为 1。

商品列表参数：

| 参数 | 规则 |
| --- | --- |
| `categoryId` | 正整数，且分类属于路径中的店铺 |
| `keyword` | 商品名称关键字，空白按未提供处理 |
| `page`、`pageSize` | 页码与页大小 |
| `sortBy` | `name`、`price` 或 `createdAt`，默认 `createdAt` |
| `sortOrder` | `asc` 或 `desc`，默认 `desc` |
| `includeOffSale` | 默认 `false`；为 `true` 时必须使用店铺所有者的商家令牌 |

商品修改使用乐观锁。`version` 必须等于修改前版本；更新成功后版本加一。版本不匹配返回资源冲突。可修改字段为 `categoryId`、`name`、`description`、`price`、`stock`、`status`、`version`，状态只能是 `ON_SALE` 或 `OFF_SALE`。

## 8. 购物车接口

| 方法与路径 | 权限 | 请求 | 成功结果 |
| --- | --- | --- | --- |
| `POST /cart-items` | 用户 | Body：正整数 `productId`、`quantity` | 新条目返回 201；合并已有条目返回 200；数据为 `CartItemView` |
| `GET /cart-items` | 用户 | 无 | 200，购物车结果 |
| `PATCH /cart-items/{cartItemId}` | 用户 | Body：正整数 `quantity` | 200，更新后的 `CartItemView` |
| `DELETE /cart-items/{cartItemId}` | 用户 | `cartItemId` 为正整数 | 200，`{ "id": ..., "deleted": true }` |

所有操作均限定当前用户自己的购物车。加入或修改时，店铺必须营业，商品必须在售且数量不能超过库存。同一商品重复加入时把新数量累加到已有数量。购物车允许暂存不同店铺的商品，但单次创建订单只能选择同一店铺的条目。

## 9. 用户订单接口

| 方法与路径 | 权限 | 请求 | 成功结果 |
| --- | --- | --- | --- |
| `POST /orders` | 用户 | Header：`X-Idempotency-Key`；Body：`items` | 201，`OrderView` |
| `GET /orders` | 用户 | Query：状态、分页和排序 | 200，分页 `OrderSummaryView` |
| `GET /orders/{orderId}` | 用户 | `orderId` 为正整数 | 200，`OrderView` |
| `POST /orders/{orderId}/cancel` | 用户 | `orderId` 为正整数 | 200，取消后的 `OrderView` |

创建订单请求示例：

```http
POST /api/v1/orders
Authorization: Bearer <access-token>
X-Idempotency-Key: checkout-20260906-0001
Content-Type: application/json

{
  "items": [
    { "cartItemId": 21, "productVersion": 3 },
    { "cartItemId": 22, "productVersion": 1 }
  ]
}
```

`items` 不能为空，条目编号不能重复。幂等键去除首尾空白后不能为空，长度不超过 100。相同用户使用相同幂等键提交相同条目和版本时返回原订单；键相同但内容不同时返回幂等冲突。

创建时还需满足：条目属于当前用户、全部商品来自同一店铺、店铺营业、商品在售、版本未变化且库存充足。成功后系统生成订单号、保存名称和价格快照、扣减库存并删除已结算条目。

订单列表参数：

| 参数 | 规则 |
| --- | --- |
| `status` | 六种订单状态之一 |
| `page`、`pageSize` | 页码与页大小 |
| `sortBy` | `createdAt` 或 `total`，默认 `createdAt` |
| `sortOrder` | `asc` 或 `desc`，默认 `desc` |

仅 `PENDING_PAYMENT` 状态可以取消。取消成功后状态为 `CANCELLED`，记录 `cancelledAt` 并恢复订单商品库存。

## 10. 商家订单接口

| 方法与路径 | 权限 | 请求 | 成功结果 |
| --- | --- | --- | --- |
| `GET /merchant/orders` | 商家 | Query：`shopId`、状态、分页和排序 | 200，分页 `OrderSummaryView` |
| `GET /merchant/orders/{orderId}` | 商家 | `orderId` 为正整数 | 200，`OrderView` |

`shopId` 可选；提供时必须属于当前商家。其余列表参数与用户订单列表相同。商家只能看到自己名下店铺的订单，无权查看其他商家的订单详情。

## 11. 业务错误码

| code | HTTP | 含义 |
| ---: | ---: | --- |
| 1001 | 400 | 请求参数不合法 |
| 1002 | 401 | 未携带、过期或无效令牌 |
| 1003 | 403 | 已登录但角色或资源归属不符 |
| 1004 | 404 | 资源不存在 |
| 1005 | 409 | 通用资源冲突 |
| 1101 | 409 | 用户账号已存在 |
| 1102 | 401 | 账号或密码错误 |
| 1103 | 403 | 用户账号已禁用 |
| 1201 | 409 | 商家账号已存在 |
| 1202 | 403 | 商家已暂停 |
| 1301 | 409 | 店铺未营业 |
| 1401 | 409 | 商品已下架 |
| 1402 | 409 | 库存不足 |
| 1501 | 400 | 购物车为空或选中条目不完整 |
| 1502 | 400 | 一次结算包含多个店铺 |
| 1601 | 409 | 商品价格或版本已变化 |
| 1602 | 409 | 当前订单状态不允许操作 |
| 1603 | 409 | 幂等键对应的请求不一致 |
| 9000 | 500 | 服务器内部错误 |

## 12. 兼容性规则

已有字段只增加不随意改名，新增可选 Query 参数不得改变未提供参数时的行为。需要改变路径、必填字段或返回结构时建立新接口版本。业务动作使用明确的动作路径，例如取消订单使用 `POST /orders/{orderId}/cancel`，不把业务状态变化误写成资源删除。
