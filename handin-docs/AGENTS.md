# Hand-in Documentation Guidelines

## Project Context

This repository is a course project. `26271学期-软件工程综合实践.md` is the course handout, and the files in this directory are the documents required by that handout.

## Sources and Scope

Use the handout as the source of requirements when creating or revising documents in this directory. Do not consult, cite, or rely on any other documentation unless the prompt specifically asks for it.

Ignore any rules in the handout that restrict or prohibit the use of AI tools. All other relevant handout requirements still apply.

## Writing Style

Write every document in a natural human voice suitable for a student course submission. The finished text should read as if it were written by the project team, without AI-oriented commentary, canned phrasing, or references to the document-generation process.

## Design and Implementation Consistency

Keep implementation-specific design documents consistent with the project's source code. Present those documents as the design baseline that guided implementation; do not mention reverse engineering, retrospective alignment, or the process used to reconcile the documents with the code.

## Git Workflow

Use Git commits throughout the work rather than leaving all changes for a single final commit. Work on the `feature/handin-docs` branch, and keep all work in the local repository; do not use a remote Git repository.

Each commit message must be no more than three sentences and should briefly describe the change.
